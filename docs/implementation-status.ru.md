# bot_astrosferum: статус реализации

Дата: 2026-07-21
Этап: Stage 3, live ICON-EU → Telegram
Среда развёртывания: управляемый оператором сервер

## Готово

- PostgreSQL 18.4 хранит пользователей, до 10 точек на пользователя и ограниченные 90 днями суточные агрегаты запросов;
- Telegram-клавиатура поддерживает сохранение/выбор точек; администратор из `.env` получает число пользователей и PNG за 30 дней;
- Light Pollution Atlas 2024 дополнен отдельным сравнением World Atlas 2015; обязательный GeoTIFF автоматически восстанавливается при старте;
- runtime использует официальный OSGeo GDAL 3.13.1 и ecCodes 2.45.0.
- имена полей поверхности нормализуются между версиями ecCodes (`VMAX_10M`/`max_i10fg`);
- админский график использует составные столбцы «успешно/с ошибкой» и календарные сутки MSK (UTC+3); меню точек имеют кнопку «Назад».

- Go `1.26.5`, `tzf v1.2.3`, `gonum/plot v0.17.0`;
- Telegram принимает native location, `59.9386, 30.3141` и `/forecast 59.9386 30.3141`;
- `/start` и `/help` объясняют запрос и интерпретацию всех семи графиков;
- пользовательское сообщение показывает выбранную модель, run ID и возраст model run относительно настраиваемого `max_stale_age`; этот порог управляет только предупреждением `⚠️ stale run` и не удерживает данные в кеше. Run ID входит в ключи point/render cache, поэтому новый опубликованный run автоматически даёт cache miss;
- язык Telegram определяется по `User.language_code`: только `ru*` получает русский интерфейс, любой другой или отсутствующий код — английский; локализованы помощь, статусы, ошибки, кнопки, подписи, погодная таблица и все заголовки/оси/легенды PNG, а render-cache разделён по языку;
- timezone определяется offline по координатам и подписывается на каждом PNG;
- DWD discovery выбирает последний полный ICON-EU цикл `00/06/12/18` с доступным `+72 h`;
- координаты вне домена ICON-EU маршрутизируются на последний полный ICON Global `00/06/12/18` на полной native global grid; CDO использует официальную статическую геометрию DWD для выбора ближайшего native-узла без обрезки источника и без второй мировой raster-копии;
- ICON Global теперь синхронизирует тот же 79-часовой 27-уровневый контракт `CLC/P/T/QC/QI + нижние U/V/TKE + HHL`, что ICON-EU, используя эквивалентные по высоте model indices со сдвигом `+46`; DWD Global TKE заканчивается на `+48 ч`, поэтому до него bundle содержит 187 сообщений/час, затем 169, cloud map остаётся полной, а гибридный Overall заканчивается без экстраполяции отсутствующей турбулентности; прямой `VIS` также остаётся недоступен в DWD Global feed;
- atomic sync скачивает pressure-level `U/V/FI/T`, не сохраняет `.bz2`, проверяет каждый бандл через ecCodes и SHA-256;
- старый pressure-level run атомарно дополняется только отсутствующими `FI/T`; scheduler независимо публикует versioned hourly surface/cloud bundle, а ecCodes 2.45 `clwmr/QI` нормализуются во внутренние `qc/qi`;
- `current` переключается атомарной symlink-операцией только после полной проверки;
- sync защищён exclusive lock; scheduler запускает проверку при старте, затем каждые 15 минут и хранит два последних run; пользовательский запрос ничего не скачивает, а читает последний полностью опубликованный набор;
- point extractor параллельно получает 25 вертикальных профилей из текущего manifest;
- независимый surface sync публикует 79 почасовых бандлов `f000…f078` с `T_2M`, `TD_2M`, `RELHUM_2M`, `CLCT/CLCL/CLCM/CLCH`, `TOT_PREC`, `U_10M`, `V_10M`, `VMAX_10M`, `PMSL`, `VIS`, `TQV` и точными столбовыми `TQC/TQI`;
- Telegram показывает 72 часа; туман берётся из прямого `VIS`, а карта облаков показывает эффективную преграду по высоте из `CLC+QC+QI` и фазовой оптической толщины;
- роса показывается только как подсказка о подготовке обогрева/бленды и не снижает seeing или практический score;
- pure-Go astronomy рассчитывает Солнце, Луну, Юпитер и Сатурн; регрессии для Санкт-Петербурга и Москвы ограничивают Sun/Moon двумя минутами от эталона, а события планет явно помечены как приближённые;
- Telegram строит семь PNG; production-индекс `3200×960` объединяет гибридный ICON TKE/MH + HMNSP99 seeing, `tau0`, эффективное облачное пропускание по `CLCT+TQC+TQI`, туман и мягкий приземный ветер;
- текстовый блок получает точечную оценку засветки из Light Pollution Atlas 2024: билинейные LPI/SQM на сетке около `30″` и честно помеченный ориентир Бортля; засветка не входит в Overall Index;
- значения в heatmap увеличены до 8 pt и сделаны полужирными, оси и bar labels также увеличены;
- старый wind-only index сохранён отдельным диагностическим графиком; direction delta равен `0°` при ветре `<2 m/s`, а `NaN` означает только отсутствие данных;
- контейнер работает от `1000:1000`, с read-only root filesystem и всеми bind mounts внутри `/opt/docker/bot_astrosferum`;
- `go test ./...`, `go vet ./...` и `doctor` проходят.

Freshness и двуязычный render развёрнуты 21.07.2026: production-бинарь успешно создал по семь ненулевых PNG для `ru` и `en`, временные проверочные каталоги удалены, основной контейнер остался `running` с `restart_count=0`, PostgreSQL — `healthy`.

## Production-изменение Overall

Аудит обезличенного исторического контрольного примера обнаружил, что
развёрнутый legacy HMNSP99-расчёт не разрешает PBL и даёт узкий ряд около
`0.70…0.77″`; smoothstep с прежней лучшей границей `0.7″` и condensate без
защиты от несогласованного `CLC` создают слишком много значений `10`.

В production развёрнута следующая схема:

- `surface-hourly-v17` публикует 17 single-level полей на каждый из 79 часов,
  включая ICON `MH`/ecCodes `mld` в метрах;
- `cloud-hourly-v4` публикует ровно 187 сообщений на каждый час:
  `CLC/P/T/QC/QI` на всех 27 выбранных model levels, `U/V` на непрерывных
  `58…74`, `TKE` на half levels `58…75` и отдельную `HHL`-геометрию;
- Masciadri `Cn²` интегрируется трапециями от поверхности до почасовой границы
  `h_PBL=clamp(ICON_MH,500,2000) m AGL`; HMNSP99 применяется только выше той
  же границы, а полный `J` даёт model-derived seeing на 500 нм;
- `tau0` рассчитывается из `integral(Cn²·|V|^(5/3)dz)`; отдельного повторного
  штрафа за направление нет, поскольку vector shear уже содержит разворот;
- приземный ветер штрафует мягко, максимум на 20%; роса исключена, возможный
  и высокий туман используют множители `0.75/0.10`;
- карта вычисляет массу каждого native слоя как
  `P_Pa/(287.05·T)·abs(HHL[k]−HHL[k+1])`, поэтому sparse levels не раздувают
  condensate path;
- unresolved-CLC guard зависит от яруса: low `0.45·C`, middle
  `0.55·0.45·C=0.2475·C`, high `0.18·0.45·C=0.081·C`; это консервативная
  инженерная неопределённость, не физическая opacity, а более сильный
  `QC/QI` optical-depth результат всегда выигрывает;
- карта применяет общий optical-depth kernel/guard policy на каждом native
  level, а Overall использует total-column `TQC/TQI` и random overlap
  `CLCL/CLCM/CLCH`; поэтому их числа не объявляются идентичными;
- point-cache schema поднята до `point-v6-native-cloud-mass-mh`, чтобы старые
  записи без `MH`, `T` и нативной толщины слоя не переиспользовались;
- version markers синхронизированы с новым контрактом:
  `seeing-hybrid-tke-mh-hmnsp99-v4`,
  `conditions-v4-dynamic-mh-cloud-guard`, `render-v10-localized` и
  `telegram-render-v7-localized`.

Server-side fixed-2-km расчёт двух сроков без подгонки
(`ground Cn² scale=1`) дал для исторического контрольного примера `2.221″` на `f042` и `3.644″` на
`f048`; ground layer содержал соответственно 88.36% и 94.43% `J`. После
подключения `MH=396 m` на обоих сроках расчёт без clamp дал
`1.9075″/2.5158″`, а production-minimum 500 м — `1.9145″/2.5478″`. Это
server-only регрессия причины ошибки, не наблюдательная калибровка. Полный
production sync `surface-hourly-v17`/`cloud-hourly-v4` для run `2026072106`
завершён, новый образ развёрнут, а live CLI-путь Telegram проверен на контрольном примере.

Последний проверенный live до нового deploy: extraction и семь PNG старой версии повторно проверены 21.07.2026 на production run `2026072100` для обезличенного исторического контрольного примера. Опубликованы 79×16 surface-полей (`surface-hourly-v16`, 1.2 GiB) и 79×19×4 model-layer полей плюс HHL (`cloud-hourly-v2`, 2.4 GiB); прежние versioned-каталоги удалены после атомарного switch. Контроль старой cloud-physics версии дал: 22.07 09:00 UTC при `CLCT=72.8%`, `TQI=0.000015 kg/m²`, `τ=0.00105` вычисленное пропускание `99.90%`, Overall `9.98`; 22.07 02:00 при `CLCT=100%`, `τ=2.78` — `6.20%` и Overall `1.03`. Первый пример теперь служит регрессией для unresolved-CLC floor, а не желаемым результатом. Output старой версии: weather `3200×1080`, overall `3200×960`, cloud obstruction `3200×1100` и четыре `1280×960`.

Добавлен bounded performance layer: surface/wind/cloud извлекаются параллельно и объединяются в один point bundle, совпавшие miss объединяются, `gob.gz` кеш хранится для двух run × 512 ячеек, RAM LRU ограничен 512 ячейками/20 GiB, а семь PNG кешируются на 48 часов (до 256 комплектов). Production использует provider-versioned point cache; старые schema автоматически игнорируются. Telegram использует шесть шардированных workers и 15-минутный request timeout, чтобы первый full-native Global point extraction успел завершиться; ecCodes/CDO делят общий лимит восемь процессов. Каждая загрузка объекта DWD по-прежнему имеет ограниченный двухминутный HTTP timeout и три попытки, а scheduler не ограничен Telegram timeout. Временные cache staging старше часа и Docker-логи сверх `3 × 10 MiB` удаляются автоматически.

Production request после смены cache schema, run `2026072100`: cold extraction `38.5 s`, render семи PNG `1.82 s`, отправка `1.75 s`, всего `42.24 s`. Повторный CLI-run получил point bundle с диска за `2 ms`; комплект семи PNG занимает около `2.7 MiB`. Render-cache содержит ровно семь файлов и по-прежнему ограничен 48 часами/256 комплектами.

Контроль нового production run `2026072106` на обезличенном историческом примере:
первичное извлечение расширенного `187×79` cloud bundle заняло `1m14s`, после
чего disk-cache hit занимает `2 ms`, а повторный полный CLI render семи PNG —
около `4.1 s`. Доступны 69 будущих часов: Overall `1.00…4.58`, точных `10`
